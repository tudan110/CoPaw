# 领域准入裁判细则（可编辑）

本系统是一套**网络管理 / 网络运维（NMS / 网管）平台**，只承载与网络管理、IT 基础设施运维
相关的业务能力。导入的技能（Skill）或外部工具（MCP）必须落在下述范围内；不属于本领域的、
属于其它专业方向的能力，一律不予导入。

---

## 一、属于本领域（IN-SCOPE，应放行）

- **故障 / 告警管理**：活动告警分析、告警收敛/降噪、根因分析（RCA）、闭环处置、与工单系统联动。
- **性能管理**：KPI/指标采集、阈值与基线、容量/趋势分析、健康检查、拨测。
- **配置管理**：设备配置查询/下发、变更管理、配置基线与合规校验、回滚。
- **资源 / 拓扑 / 库存**：CMDB、网元、链路、端口、IP/号码资源、应用拓扑、物理/逻辑拓扑。
- **巡检与例检**：周期巡检、专项巡检、巡检报告生成。
- **网络运维自动化**：脚本编排、批量操作、应急预案执行（在受控范围内）。
- **IT / 网络基础设施监控**：服务器/数据库/中间件/容器/网络设备的监控与运维。
- **ITSM / 工单流转**：工单创建、派发、催办、关闭（按权限与审批策略）。
- **运维报表与 SLA**：可用性、SLA、运维周报/月报、复盘材料。
- **与网络/运维强相关的安全合规**：网络侧合规审计、变更审计、操作留痕。
- **通信网典型领域**：核心网、承载网、传输网、接入网、5G、基站、光缆、PON/OLT/ONU、IDC 等。

> 判断要点：技能/工具的**主要用途**是否服务于"管好网络 / 管好运维"。是 → 放行。

---

## 二、不属于本领域（OUT-OF-SCOPE，应拒绝）

- 财务 / 会计 / 报销 / 发票
- 医疗 / 病历 / 临床诊断 / 处方
- 法律 / 合同审查 / 诉讼
- 人力资源 / 招聘 / 简历 / 绩效
- 市场营销 / SEO / 社交媒体运营 / 文案创作
- 电商 / 订单履约 / 选品
- 金融交易 / 炒股 / 加密货币
- 与运维无关的通用内容创作（写小说、写作文、做菜谱、旅行攻略等）
- 通用机器翻译 / 通用文本摘要（仅当其唯一用途即此，且未声明任何网管场景）

> 即使技能"做得很好"，只要主要用途落在上述方向 → 拒绝，并提示"当前系统暂不支持导入其他专业的技能"。

---

## 三、灰区 / 通用工具（BORDERLINE，从严判断）

shell/命令行、文件读写、grep、HTTP 客户端、REST 调用、数据库查询/SQL、Kubernetes/Docker、
Prometheus/Grafana、Jira/Confluence、钉钉/飞书/Slack、邮件发送、浏览器/爬虫、通用翻译/摘要 ……
这类工具**本身既能服务网管也能服务别的领域**。判断方式：

- 若其名称/描述/内容**明确声明用于网管/网络运维场景**（例如"用于查询网管 CMDB 数据库""巡检脚本执行器"
  "向运维群推送告警"），则视为 IN-SCOPE → 放行。
- 若只是一个**没有任何网管场景声明的纯通用工具** → 视为不够明确，按从严原则**不予导入**，
  并提示可联系管理员将其加入白名单。

---

## 四、判定标准小结

1. 先看主要用途落在 IN-SCOPE 还是 OUT-OF-SCOPE。
2. 通用工具看是否声明了网管场景；没声明 → 从严拒绝。
3. 拿不准（置信度低）→ 从严拒绝，留管理员白名单作为逃生口。

## 五、参考示例（few-shot）

- 「activealarm-diagnose：面向单条活动告警做根因分析与闭环处置，联动 CMDB 与工单」→ relevant=true, category="故障/告警管理", reason="围绕活动告警做根因与闭环，典型网络故障管理"。
- 「oracle-tablespace-inspection：巡检 Oracle 表空间、锁等待、慢 SQL、主备延迟，异常自动生成工单」→ relevant=true, category="数据库运维巡检", reason="数据库基础设施巡检并联动工单，属 IT 运维范畴"。
- 「resume-screener：解析候选人简历并按岗位打分排序」→ relevant=false, category="人力资源/招聘", reason="简历筛选属 HR 领域，与网络管理无关"。
- 「invoice-ocr：识别发票图片并抽取金额、税号、开票方」→ relevant=false, category="财务/票据", reason="票据识别属财务领域，与网管无关"。
- 「shell-runner：执行任意 shell 命令并返回输出」（无任何网管场景声明）→ relevant=false(低置信), category="通用工具", reason="纯通用命令执行工具，未声明网管用途，按从严原则不予导入；如确需可加白名单"。
- 「cmdb-sql-query：连接网管 CMDB 数据库执行只读 SQL 查询资源信息」→ relevant=true, category="资源/CMDB", reason="明确用于网管 CMDB 查询，属资源管理"。
