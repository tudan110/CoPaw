# AI 辅助轻应用开发方案

## 一、需求背景

在 IT 运维和业务交付场景中，客户经常需要定制化的展示页面：

- 报表呈现（设备统计、告警趋势、容量分析等）
- 固定查询（按条件查 CMDB、查指标、查告警历史）
- 任务固化（巡检报告页、故障复盘页、运营看板）

但客户通常不具备前端开发能力，无法自行编写 HTML/JS/CSS。

**核心诉求**：用户通过自然语言对话描述需求，AI 充当程序员角色，生成可运行的 HTML 应用页面，发布后可在"应用市场"中快速访问使用。

## 二、与现有功能的关系

| 功能 | 定位 | 区别 |
|------|------|------|
| 轻应用工坊（现有） | 对话问答的归档与复用 | 保存的是"对话流程"，不是独立页面 |
| **AI 辅助应用开发（本需求）** | 用户描述 → AI 写代码 → 发布独立应用 | 产出物是可独立运行的 HTML 页面 |
| HTML 成果发布服务（已有方案） | 底层发布能力 | 本需求的发布环节依赖该服务 |

## 三、核心能力定义

### 3.1 对话式开发

用户用自然语言描述需求，AI 生成完整可运行的 HTML 页面。

**交互示例**：

```
用户：帮我做一个按地市统计网络设备数量的柱状图，用 ECharts
AI：[生成 HTML 页面，包含 ECharts 柱状图，JS 调用 CMDB 接口查询数据]
用户：颜色改成蓝色渐变，再加一个饼图显示厂商占比
AI：[修改 HTML，新增饼图]
用户：可以了，发布
AI：[调用发布服务，返回访问链接]
```

### 3.2 实时预览

- 每次 AI 生成或修改 HTML 后，用户可以立即预览效果
- 预览环境与最终发布环境行为一致
- 不满意可以继续用自然语言迭代修改

### 3.3 数据对接

生成的 HTML 页面中的 JS 可以调用后端 API 查询真实数据：

- CMDB 资源查询（设备、拓扑、模型）
- 指标数据查询（性能、容量、趋势）
- 告警数据查询（当前告警、历史告警、统计）
- 工单数据查询（状态、进度、统计）
- 其他已有业务 API

### 3.4 发布上线

用户确认满意后，一键发布：

- 生成稳定的访问 URL
- 在应用市场中可见
- 支持分享给其他用户

### 3.5 应用管理

已发布的应用支持全生命周期管理：

- 查看 / 打开
- 修改（重新进入对话，迭代开发）
- 版本管理（保留历史版本）
- 下线 / 删除
- 分享 / 权限控制

## 五、关键技术问题

### 5.1 页面内 JS 调接口的鉴权与代理

生成的 HTML 页面在浏览器中运行，需要调用后端 API 获取数据。面临的问题：

| 问题 | 解决方案 |
|------|---------|
| 跨域（CORS） | 通过 API 网关统一代理，或发布服务同域托管 |
| 鉴权（Token） | 方案 A：页面访问时注入临时 token；方案 B：发布服务代理转发并附加鉴权 |
| 接口安全 | 限定可调用的 API 白名单，避免越权访问 |

**推荐方案**：发布服务提供 API 代理层（`/api-proxy/...`），页面内 JS 调用相对路径，由发布服务统一附加鉴权信息转发到后端。

### 5.2 数据刷新策略

| 策略 | 适用场景 | 说明 |
|------|---------|------|
| 实时查询 | 固定查询类应用 | 每次打开页面时 JS 调接口查最新数据 |
| 定时刷新 | 看板类应用 | 页面内 setInterval 定时轮询 |
| 静态快照 | 报告类应用 | 发布时数据已内嵌，不再更新 |

AI 在生成页面时根据用户需求场景自动选择合适策略。

### 5.3 应用迭代

用户说"把图表颜色改一下"时，需要能在原应用基础上修改并重新发布：

- 每个应用关联一个"开发会话"
- 会话中保留 AI 生成的完整代码上下文
- 用户可以随时回到开发会话继续迭代
- 修改后重新发布，覆盖原 URL 或生成新版本

### 5.4 AI 代码生成质量保障

- **模板库**：常见场景（ECharts 图表、表格、表单）提供参考模板
- **API 文档注入**：将可用的业务 API 文档作为上下文提供给 AI
- **沙箱校验**：生成后在沙箱中运行校验，确保无语法错误
- **安全审查**：检查生成的代码不包含危险操作（XSS、外部请求等）

## 六、实施路径

### Phase 1：MVP — 静态 HTML 生成与发布

**目标**：跑通"对话 → 生成 HTML → 预览 → 发布 → 访问"全链路

- AI 生成自包含的 HTML 页面（数据内嵌，不调接口）
- 预览使用 iframe 沙箱
- 发布存储到本地文件系统 / PVC
- 应用市场展示已发布应用列表

**交付物**：
- 对话开发入口页面
- HTML 预览组件
- 发布 API + 存储
- 应用列表 API + 展示页面

### Phase 2：动态数据对接

**目标**：生成的页面可以调用真实 API 获取实时数据

- 发布服务增加 API 代理层
- AI 代码生成时注入 API 调用代码
- 接口白名单与权限控制
- 支持实时查询和定时刷新

### Phase 3：应用迭代与版本管理

**目标**：已发布的应用可以继续修改迭代

- 应用与开发会话关联
- 版本历史管理
- 回滚能力
- 应用分享与权限

### Phase 4：平台化能力

**目标**：形成通用的 AI 辅助应用开发平台

- 模板市场（常见场景模板）
- 组件库（可复用的图表、表格组件）
- 多用户协作
- 应用审批发布流程
- 访问统计与运营分析

## 七、与已有方案的衔接

本方案的"发布"环节直接复用 `html-artifact-publishing-service` 方案设计：

- 存储层：MinIO / S3 / OSS
- URL 管理：稳定访问链接
- 生命周期：版本、归档、清理

本方案新增的是"发布之前"的部分：

- 对话式需求输入
- AI 代码生成
- 实时预览与迭代
- 数据 API 对接

两个方案组合起来形成完整链路：**用户描述 → AI 开发 → 预览确认 → 发布上线 → 稳定访问**。
