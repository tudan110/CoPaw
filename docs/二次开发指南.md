# 数字员工平台二次开发指南

> 基于 QwenPaw（CoPAW）构建企业级数字员工平台的二次开发实践。

---

## 一、概述

### 1.1 什么是 QwenPaw

[QwenPaw](https://github.com/modelscope/qwenpaw)（曾用名 CoPAW）是一个开源的 AI 个人助手框架，提供：

- **FastAPI 后端**：对话管理、多渠道接入（钉钉、飞书、Discord、Telegram、微信等）、技能（Skills）执行、定时任务
- **React 管理后台**（`console/`）：Agent 配置、渠道管理、技能管理
- **模型提供者管理**：支持 OpenAI、通义千问、百度文心、昆仑等多种 LLM 提供商

### 1.2 我们做了什么

我们在 QwenPaw 基础上做了**垂直领域数字员工平台**的二次开发，扩展内容包括：

| 层次 | 扩展方式 | 说明 |
|------|----------|------|
| **后端 API** | `extensions/api/` | 新增 30+ API 模块，涵盖告警分析、故障诊断、知识库、大屏、SSO 等 |
| **前端 Portal** | `portal/` | 独立 React 前端，提供数字员工对话、运维面板、自监控等界面 |
| **集成层** | `extensions/integrations/` | 对接夜莺监控、告警工单、CMDB 等外部系统 |
| **安全加固** | `extensions/security/` | 出口脱敏、高危操作边界校验 |
| **可追溯性** | `extensions/traceability/` | Agent 执行链路追踪，存入 JSONL |

### 1.3 核心原则

```
src/qwenpaw/               ← 上游核心（视为依赖，尽量不改）
src/qwenpaw/extensions/    ← 我们的二次开发代码（主力阵地）
portal/                    ← 独立前端（数字员工门户）
```

**不要修改 `src/qwenpaw/` 核心代码**，新增功能全部放在 `extensions/` 下。如果确实需要改动核心，必须显式评估并记录理由。

### 3.2 新增一个 API 端点

**Step 1：在 `portal_backend.py` 中直接添加路由**

```python
# src/qwenpaw/extensions/api/portal_backend.py

@router.get("/my-new-feature")
async def get_my_feature():
    return {"data": "hello"}
```

**Step 2：或创建独立子路由器模块**

```python
# src/qwenpaw/extensions/api/my_feature_api.py
from fastapi import APIRouter

router = APIRouter(prefix="/api/portal", tags=["my-feature"])

@router.get("/my-feature/config")
async def get_config():
    return {"enabled": True}
```

然后在 `portal_backend.py` 中注册：

```python
from .my_feature_api import router as my_feature_router
# ... 在文件顶部和其他 router.include_router 一起
router.include_router(my_feature_router)
```

**Step 3：前端通过 `/portal-api/` 前缀调用**

```typescript
// portal/src/api/myFeature.ts
const API_BASE = "/portal-api";

export async function fetchMyFeatureConfig() {
  const res = await fetch(`${API_BASE}/my-feature/config`);
  return res.json();
}
```

### 3.3 设置存储模式

多数设置模块使用 SQLite + 命名空间表，通过 `settings_store.py` 或 `provider_settings_base.py` 基类快速实现：

```python
# 继承通用设置存储
from qwenpaw.extensions.api.settings_store import SettingsStore

class MyFeatureSettingsStore(SettingsStore):
    """我的功能设置。"""
    NAMESPACE = "my_feature"  # SQLite 表名

    KEYS = [
        "enabled",
        "api_key",
        "endpoint_url",
    ]
```

### 3.4 与核心 Agent 对话

Portal 通过核心 API 与 Agent 对话：

```typescript
// portal/src/api/copawChat.ts
// 创建会话 → 发送消息 → SSE 流式接收回复
const API_BASE = "/copaw-api";

export async function createSession(agentId: string) {
  return fetch(`${API_BASE}/chats`, {
    method: "POST",
    body: JSON.stringify({ agent_id: agentId }),
  });
}

// 消息通过 SSE (Server-Sent Events) 流式返回
```

### 5.2 典型模式

```python
# src/qwenpaw/extensions/integrations/my_external_system.py
import httpx
from qwenpaw.extensions.runtime_data_paths import EXTENSIONS_DATA_DIR

class MyExternalSystemClient:
    """外部系统 API 客户端。"""
    
    def __init__(self):
        self.base_url = os.getenv("MY_SYSTEM_URL", "https://api.example.com")
        self.client = httpx.AsyncClient(timeout=30)
    
    async def fetch_data(self, query: str) -> dict:
        resp = await self.client.get(f"{self.base_url}/data", params={"q": query})
        resp.raise_for_status()
        return resp.json()
```

## 六、安全与可追溯性

### 6.1 安全加固

安全模块在应用启动时自动安装，无需手动配置：

```python
# src/qwenpaw/app/_app.py
from ..extensions.security import install_security_hardening
install_security_hardening()  # 安装出口脱敏 + 高危操作校验
```

- **出口脱敏** (`output_guard.py`)：所有渠道出站消息在发送前自动打码凭证/密钥
- **高危边界校验** (`high_risk_boundary.py`)：启动时检查 CRITICAL/HIGH 工具规则是否已配置为自动拒绝

### 6.2 链路追踪

追踪模块自动记录 Agent 执行的每一步：

```python
from qwenpaw.extensions.traceability import trace_store
trace_store.record_event(session_id, event_type, payload)
```

数据存储在 `WORKING_DIR/chat_traces/` 下的 JSONL 文件，通过 Portal 自监控面板可查看。

## 八、最佳实践

### 8.1 开发规范

1. **不要改核心**：所有新增代码放在 `extensions/` 下，保持上游可升级
2. **模块化**：每个功能领域独立一个文件/目录，避免 `portal_backend.py` 无限膨胀
3. **类型安全**：后端使用 Pydantic 模型，前端使用 TypeScript 类型，前后端类型对齐
4. **错误处理**：API 返回统一错误格式，前端捕获并展示友好提示
5. **日志**：使用 `logging.getLogger(__name__)`，不要用 `print`

### 8.2 API 设计

- 扩展 API 使用 `prefix=/api/portal`，不影响核心 API (`/api/`)
- 前端通过 Vite 代理 `/portal-api/*` → `/api/portal/*`
- 生产环境静态文件由 FastAPI 直接 serve

### 8.3 数据存储

- 扩展数据统一放在 `WORKING_DIR/extensions/` 下
- 使用 `runtime_data_paths.py` 管理路径，不要硬编码
- 设置类数据使用 SQLite（单文件，零运维）
- 文件类数据（报告、制品）使用目录存储

### 8.4 对话集成

- Portal 通过核心对话 API 与 Agent 交互
- 使用 SSE 流式接收回复，实现打字机效果
- 会话历史存储在本地 `localStorage`（`conversationStore.ts`）

### 8.5 前端性能

- 页面组件使用 `lazyWithRetry` 懒加载
- 大屏组件使用 `Suspense` + fallback
- ECharts 图表按需渲染，避免无效重绘
