# 故障报告模板

本模板来自《城域网核心路由器光模块老化故障根因定位方案》文档，
用于人工书写正式故障报告时参考；脚本的 Markdown 输出（见
`scripts/diagnose_optical_aging.py` 里的 `render_markdown()`）在字段
含义上与本模板一一对应，但格式做了适合聊天窗口展示的调整。

## 原始模板

```
故障编号：XXXX
发生时间：YYYY-MM-DD HH:MM
故障现象：核心路由器A端口GE0/0/1误码率上升，影响约10万用户
根因定位：光模块老化（接收光功率-23.5dBm，偏置电流68mA，温度78°C）
处置动作：切换备用链路 → 更换光模块 → 恢复主链路
修复时间：HH:MM（耗时XX分钟）
改进建议：增加光模块寿命预警，温度超过65°C自动告警
```

## 字段与脚本输出的对应关系

| 模板字段 | 脚本输出中的对应内容 |
|----------|----------------------|
| 故障编号 / 发生时间 | 需由调用方（人工或 Agent）另行提供，脚本不生成 |
| 故障现象 | `--port` + `--affected-users` 拼出的端口与影响范围 |
| 根因定位 | `root_cause.conclusion`（含关键异常参数数值） |
| 处置动作 | `remediation_suggestions` 列表 |
| 修复时间 | 需人工事后补充，脚本不产出 |
| 改进建议 | `remediation_suggestions` 里的"预防措施"条目 |

## Agent 使用建议

如果用户明确要求"生成故障报告"（而不只是"帮我看看这个端口是不是坏
了"），应在脚本 Markdown 输出的基础上，补充故障编号、发生时间、修复
时间等脚本无法自动获得的字段，再按上面的模板整理成最终报告，而不是
直接把脚本原始输出当成故障报告发出去。
