# 参数正常范围与故障现象参考表

本文档内容整理自《城域网核心路由器光模块老化故障根因定位方案》，
是脚本 `scripts/utils/thresholds.py` 里各项数值的来源。

## 故障现象

| 现象维度 | 具体表现 |
|----------|----------|
| 用户侧 | 部分用户间歇性丢包、视频卡顿、网页加载缓慢，严重时段出现短暂断连 |
| 网管告警 | 核心路由器上报"光模块接收光功率偏低"、"CRC校验错误增长"、"链路误码率超阈值"、"端口频繁Flap" |
| 性能指标 | 该端口入方向 CRC 错误计数持续增长，光模块温度偏高（>70°C），发送光功率正常但接收光功率接近接收灵敏度下限 |
| 业务影响 | 影响该核心路由器下挂的多个 BRAS/vBRAS 域，覆盖约 10 万宽带用户，非全阻但体验劣化 |

**典型特征**：故障呈渐进式发展，初期偶发丢包，随时间推移恶化，夜间
低谷期可能自行恢复（温度降低），白天高峰期加重。

## 分析维度（光模块老化机理相关）

| 分析点 | 说明 |
|--------|------|
| 光模块自身参数 | 接收光功率、发送光功率、偏置电流、温度、电压，与出厂阈值对比 |
| 链路质量 | CRC 错误计数、误码率（BER）、FEC 纠错前/后统计 |
| 端口稳定性 | Link up/down 次数、Flap 频率、恢复时间 |
| 对端设备 | 对端端口光参数、是否也存在类似异常（排除光纤问题） |
| 环境因素 | 机房温度、设备风扇转速、是否有临近设备高温影响 |
| 历史趋势 | 该光模块在过去几天/几周的参数变化曲线，判断是否为渐进式劣化 |
| 同类对比 | 同一板卡其他光模块参数是否正常，排除板卡电源或背板问题 |

## 指标验证参数表（脚本主要依据）

| 参数 | 正常范围 | 故障值示例 | 判断 |
|------|----------|------------|------|
| 接收光功率 | -19 ~ -5 dBm | -23.5 dBm | 低于接收灵敏度（典型 -22 dBm） |
| 发送光功率 | -5 ~ 0 dBm | -3.2 dBm | 正常 |
| 偏置电流 | 5 ~ 50 mA | 68 mA | 偏高，表明激光器老化 |
| 温度 | 0 ~ 70 °C | 78 °C | 超温，加速老化 |
| CRC错误计数 | 0 | 持续增长，速率约 100/s | 严重误码 |

对应脚本里的常量：`RX_POWER_NORMAL_RANGE`、`RX_POWER_SENSITIVITY_LIMIT`、
`TX_POWER_NORMAL_RANGE`、`BIAS_CURRENT_NORMAL_RANGE`、
`TEMPERATURE_NORMAL_RANGE`、`TEMPERATURE_WARNING_THRESHOLD`、
`CRC_RATE_NORMAL`（定义于 `scripts/utils/thresholds.py`）。

> 温度预警阈值（65°C）来自文档"预防措施"章节的建议，比正常上限
> （70°C）提前 5°C，用于给运维留出提前介入的时间。

## 拓扑-时序传播延迟经验值

- 核心 → 汇聚的告警传播延迟，经验范围约 **1~2 分钟**
- 对应脚本常量：`TOPOLOGY_PROPAGATION_DELAY_RANGE_MIN`
