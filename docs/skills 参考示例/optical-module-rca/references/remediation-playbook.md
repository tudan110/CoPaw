# 处置预案与建议方案

本文档内容整理自《城域网核心路由器光模块老化故障根因定位方案》，
是脚本 `build_remediation_suggestions()` 给出建议的依据。

## 紧急止血（立即执行）

| 操作 | 说明 | 风险 |
|------|------|------|
| 切换备用链路 | 若该核心路由器与对端有备用链路（如主备或负载分担），将该端口流量切换至备用链路 | 需确认备用链路容量充足，避免过载 |
| 光模块复位 | 执行 shutdown / no shutdown 重置端口，临时清除 CRC 计数 | 可能短暂断流，若光模块已严重老化，复位后可能无法恢复 |
| 降低端口速率 | 若支持，将速率从 10G 强制降至 1G，降低误码率（牺牲带宽保业务） | 影响带宽，需评估是否可接受 |

## 根因修复（计划内操作）

| 操作 | 说明 | 优先级 |
|------|------|--------|
| 更换光模块 | 准备同型号光模块（如 SFP+-10G-LR），在业务低谷期更换 | 最高 |
| 清洁光纤接头 | 更换前清洁光纤连接器，排除灰尘导致的光衰 | 配合更换 |
| 检查对端光模块 | 若对端接收光功率也偏低，同步更换对端光模块 | 视情况 |

## 预防措施（中长期）

| 措施 | 说明 |
|------|------|
| 光模块寿命监控 | 建立光模块参数基线，定期采集偏置电流、温度，预测剩余寿命 |
| 备件管理 | 核心路由器光模块备件按 10% 比例储备，优先存放易老化型号 |
| 环境优化 | 检查机房空调、设备风扇，确保光模块工作温度在 40°C 以下 |
| 自动切换策略 | 配置链路质量触发自动切换（如 CRC 错误率超阈值自动切至备用链路） |

## 脚本里的分级映射

脚本 `determine_root_cause()` 会把诊断结果归到"正常 / 一般 / 严重 /
待确认"四档，`build_remediation_suggestions()` 按下面的规则给建议
（这是对文档处置预案的简化映射，实际处置仍需结合人工判断）：

| 严重程度 | 触发条件 | 给出的建议 |
|----------|----------|------------|
| 正常 | 无异常指标 | 无需处置 |
| 一般 | 1~2 项指标异常 | 紧急止血（切换备用链路） |
| 严重 | ≥3 项指标异常 | 紧急止血 + 根因修复（更换光模块） |
| 待确认 | 对端接收光功率也异常 | 先排查光纤和对端，而非直接更换本端光模块 |

无论哪种情况，都会补充一条"预防措施"建议（建立参数基线、定期采集），
这是文档强调的中长期改进方向，不应该只做完一次性修复就结束。
