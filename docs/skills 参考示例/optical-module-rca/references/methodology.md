# 分析思路与步骤（四步法）

本文档内容整理自《城域网核心路由器光模块老化故障根因定位方案》，是本
Skill 的核心方法论依据。全部内容仅来自该文档，不涉及任何外部系统。

采用 **"降噪 → 拓扑定位 → 指标验证 → 根因确认"** 四步法。

## 第一步：告警降噪（过滤无关告警）

- **时间窗去重**：同一端口 Flap 告警在 ±30 秒内只保留首条
- **拓扑压缩**：该核心路由器下挂的 BRAS、OLT 等设备若上报"链路质量劣化"
  告警，归并至该核心路由器端口
- **业务影响加权**：以用户投诉量、TCP 重传率、视频卡顿率为锚点，确认该
  端口确实是影响业务的主要瓶颈

**输出**：候选告警压缩至该核心路由器特定端口（如 GE0/0/1）的光模块
告警。

> 这一步是人工/上游告警系统的工作，本 Skill 的脚本从"已经降噪完成的
> 单个端口告警"开始处理。

## 第二步：拓扑-时序双约束因果链推理

- **拓扑方向**：该端口位于核心层，下挂汇聚层、接入层，属于"上游"设备。
  下游设备（BRAS、OLT）的告警时间应晚于该端口告警。
- **时序验证**：检查该端口 CRC 错误突增的时间点（T0），下游设备丢包率
  上升时间点（T0+Δt），Δt 应在合理传播延迟内（核心→汇聚约 1-2 分钟）。
- **路径唯一性**：若该核心路由器与对端之间有备用链路，需确认备用链路
  是否正常。若备用链路正常且流量未切换，说明主链路光模块问题尚未触发
  保护切换（因非全阻，仅误码率高）。

**输出**：初步锁定根因为"核心路由器 A 端口 GE0/0/1 光模块性能劣化"。

## 第三步：指标验证（确认光模块老化）

登录设备采集详细参数，对照 [threshold-reference.md](threshold-reference.md)
里的正常范围表逐项判断。

同时检查对端设备光模块参数：若对端接收光功率也偏低，则可能是光纤衰减
过大；若对端正常，则问题在本端光模块。

## 第四步：根因判定

综合以上信息给出根因结论和置信度。文档给出的示例判定：

> **核心路由器 A 端口 GE0/0/1 的光模块老化，表现为接收光功率过低、
> 偏置电流过高、温度超标，导致 CRC 错误持续增长，引起下挂用户间歇性
> 丢包和体验劣化。**

置信度：95%（排除光纤和对端问题后）。
