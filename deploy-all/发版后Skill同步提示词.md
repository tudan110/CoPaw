# 发版后 Skill 同步提示词

## 背景

当智观平台使用**新镜像重新部署**，但**沿用旧 PVC** 时，`/app/working/` 中的工作区文件不会自动更新。
这时可能出现：

- PVC 中的 skill 文件仍是旧版本
- 镜像内 skill 已更新，但运行时仍使用旧文件
- PVC 中残留历史调试脚本、临时文件、已废弃说明文件

如果是**首次部署**、PVC 尚未创建，则不存在这个问题；
如果是**复用旧 PVC 的升级发布**，则建议在发版后补做一次 **Skill 文件同步**。

---

## 使用提示词

```text
我刚用新镜像重新部署了智观平台，这次沿用了旧 PVC，没有重建工作区。
请帮我在容器内执行一次“Skill 文件同步”，把镜像内置的最新 skill 文件同步到 PVC 挂载目录。

同步目标：
- 源目录：/app/.working.backup/
- 目标目录：/app/working/

任务要求：
1. 先对比镜像内置目录与 PVC 工作区目录的差异
2. 仅同步 skills 相关内容，不要改动 settings.db、日志、上传文件、缓存、数据库等运行时数据
3. 将镜像中新增或更新的 skill 文件同步到 PVC 对应路径
4. 将 PVC 中已不存在于新镜像中的旧 skill 文件删除（例如历史调试脚本、临时文件、废弃说明文件等）
5. 排除所有 .env 文件，绝不覆盖运行时环境配置
6. 覆盖所有智能体/工作区中的 skill 目录，包括但不限于：
   - gateway
   - query
   - fault
   - order
   - inspection
   - knowledge
   - 以及当前工作区中实际存在的其他智能体 skill 目录
7. 如果目标目录不存在，按镜像内置目录结构自动创建
8. 同步完成后，再执行一次 diff，确认 skill 相关目录已经一致
9. 输出最终同步结果摘要：新增了哪些文件、更新了哪些文件、删除了哪些文件；如果有跳过项，也明确说明原因

注意事项：
- .env 文件属于环境运行配置，不同环境可能不同，绝不覆盖
- 只处理 skill 目录及其脚本、配置、说明文件，不要误动其他业务数据
- 如果只是 PVC 中残留的临时/调试文件，直接清理
- 如果发现某些差异不属于 skill 范围，先列出来，不要擅自删除
- 先做一次 dry-run/差异预览，再执行正式同步；正式同步后再做最终校验
```

---

## 核心原则

1. **只同步 Skill 相关目录**  
   不要对整个 `/app/working/` 做无差别覆盖或删除。

2. **保护运行时数据**  
   `settings.db`、日志、缓存、上传文件、数据库等内容不属于 skill 发布物，不能误删。

3. **绝不覆盖 `.env`**  
   `.env` 属于环境差异配置，必须保留目标环境现状。

4. **同步后必须复核**  
   正式同步完成后，要再次做 diff，确保结果符合预期。

5. **先预览、后执行**  
   优先 dry-run / 差异预览，确认范围后再正式同步。

---

## 适用场景

适用于以下情况：

- 新镜像已发布
- Kubernetes / k3s 部署复用了旧 PVC
- skill 脚本、说明、配置文件在镜像中有更新
- 需要清理 PVC 中旧版本遗留文件

不适用于以下情况：

- 首次部署、PVC 尚未初始化
- 仅修改运行时配置（如 `.env`、数据库内容）
- 仅需要检查差异、暂不执行同步
