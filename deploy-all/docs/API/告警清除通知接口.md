# 告警清除通知接口对接说明

**接口地址**：

| 调用方场景 | 地址 |
|---|---|
| 直连部署（宿主机访问） | `http://<IP>:8088/api/portal/real-alarms/clear-notifications` |
| k3s / k8s 集群外访问（NodePort） | `http://<IP>:30088/api/portal/real-alarms/clear-notifications` |
| k3s / k8s 集群内访问（Service 名称） | `http://qwenpaw:8088/api/portal/real-alarms/clear-notifications` |

> 集群内调用（如 INOE 也部署在同一 k3s/k8s 集群中）推荐直接用 Service 名称 `qwenpaw`，无需写 IP 和 NodePort。跨命名空间时使用完整域名：`http://qwenpaw.<namespace>.svc.cluster.local:8088/...`，`<namespace>` 替换为 QwenPaw 实际部署的命名空间。

**用途**：INOE 侧将一条告警标记为"已清除"后，调用此接口通知我们。我们收到后会自动在后台验证告警是否真正恢复，并将结果更新到告警台账。

**鉴权**：无需 Token，直接调用即可。

---

## 请求格式

- **Method**：`POST`
- **Content-Type**：`application/json`

### 请求体字段

| 字段 | 类型 | 是否必填 | 说明 |
|------|------|----------|------|
| `alarmuniqueid` | string | **必填** | 告警唯一标识，对应告警列表接口里的 `alarmuniqueid` 字段 |
| `devId` | string | 选填 | 设备/资源 ID |
| `canceltime` | string | 选填 | 告警清除时间，格式 `YYYY-MM-DD HH:MM:SS` |
| `clearType` | string | 选填 | 清除方式，`auto` 或 `manual` |
| `operator` | string | 选填 | 清除操作人 |
| `reason` | string | 选填 | 清除原因 |

> 字段名也接受驼峰写法，例如 `alarmId`、`clearTime`，与原生 INOE 字段名均可，无需转换。

---

## 请求示例

```bash
# 直连部署用 8088，k3s NodePort 用 30088
curl -X POST http://<IP>:8088/api/portal/real-alarms/clear-notifications \
  -H "Content-Type: application/json" \
  -d '{
    "alarmuniqueid": "ALM-2025-00123456",
    "devId": "RES-001",
    "canceltime": "2025-06-12 14:30:00",
    "clearType": "manual",
    "operator": "张三",
    "reason": "重启设备后告警消失"
  }'
```

---

## 响应示例

HTTP 200，调用成功：

```json
{
  "status": "accepted",
  "eventId": 42,
  "alarmId": "ALM-2025-00123456",
  "tracked": true,
  "deduped": false,
  "nextVerifyAt": "2025-06-12T14:32:00+08:00",
  "verificationEnabled": true
}
```

| 字段 | 说明 |
|------|------|
| `status` | `accepted` 表示已受理 |
| `eventId` | 本次事件的内部记录 ID |
| `tracked` | `true` 表示该告警在台账中存在，已进入验证队列 |
| `deduped` | `true` 表示该告警已有进行中的验证任务，本次通知被合并（可以重复推，不会重复触发） |
| `nextVerifyAt` | 预计开始验证的时间 |

---

## 注意事项

- **可以重复推送**：同一告警多次推送不会有副作用，我们会自动去重。
- **必填字段只有一个**：`alarmuniqueid`（或写作 `alarmId` / `id`），其余都是选填。
- **推完即返回**：接口立即返回 `accepted`，验证在后台异步进行，不会阻塞你们的流程。
- **错误响应**：若 `alarmuniqueid` 缺失，返回 HTTP 422；服务异常返回 HTTP 500。
