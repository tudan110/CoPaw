# 网络层故障根因分析（9场景）

## 1. 物理链路故障

**故障现象**：网络设备端口状态变更为Down，链路中断告警触发，业务流量经过该链路时丢包或中断，相关业务可用性下降或不可达。

**根因类型**：
- 光纤中断（光纤被挖断、剥离、弯曲过度）
- 端口硬件故障（光模块损坏、端口芯片过热）
- 光模块老化（渐进式性能劣化：偏置电流/温度持续升高、接收光功率渐降至灵敏度下限，区别于突发性中断）
- 双工模式不匹配（一端自协商、另一端半双工）
- 线缆老化或接头松动（长期运行导致物理损耗）
- VLAN标签不匹配导致链路协商失败

**分析步骤**：
1. **告警识别**：接收到设备syslog上报的Link Down告警，或接口状态变更的阈值告警（接口从Up变为Down），确认告警设备IP、接口名称、告警时间。
2. **拓扑关联**：通过网络拓扑查找故障链路的上下游设备、对端接口，确认链路在拓扑中的位置和承载的业务流量。
3. **性能指标分析**：检查同一链路对端设备是否也有对应Link Down告警；查看该接口的性能指标（CRC错误率、输入输出错误计数、丢包率）是否在告警前已有异常升高。若怀疑光模块老化（未Down但误码持续），采集光模块参数并与下表阈值对比，同时拉取该模块过去几天/几周的历史趋势曲线，判断是否为渐进式劣化（典型特征：初期偶发丢包、夜间低谷自行缓解、白天高峰加重，与温度正相关）：

   | 参数 | 正常范围 | 老化提示 |
   | --- | --- | --- |
   | 接收光功率 | -19 ~ -5 dBm | 接近或低于接收灵敏度下限（典型 -22 dBm） |
   | 发送光功率 | -5 ~ 0 dBm | 正常范围内可排除本端发送侧问题 |
   | 偏置电流 | 5 ~ 50 mA | 偏高（如 >65 mA）提示激光器老化 |
   | 温度 | 0 ~ 70 °C | 超温（如 >70 °C）加速老化，形成恶性循环 |
   | CRC错误计数 | 0 | 持续增长（速率随温度/负荷波动）视为严重误码 |

4. **根因判定**：
   - 若两端端口均Down且无CRC错误累积 → 光纤中断或物理断开
   - 若仅单端Down且对端正常 → 本端端口硬件故障或接头松动
   - 若端口Up但CRC错误率持续升高，且接收光功率/偏置电流/温度命中上表老化区间、历史趋势渐进恶化 → 光模块老化（同时检查对端：若对端接收光功率也偏低，优先怀疑光纤衰减而非模块老化；对端正常则问题在本端模块）
   - 若端口Up但CRC错误率持续升高、光模块参数正常 → 线缆老化或双工不匹配
5. **影响评估**：通过应用拓扑关联受影响的业务流量路径，评估是否存在备份链路切换，以及业务受影响范围。

**⚑ 处置建议（先止血 · 后修复，按影响范围决策）**
- 🚑 **紧急预案（止血/降损）**：有等价/备份链路 → 优先将受影响业务流量切换/迁移到正常链路先行恢复（需确认备用链路容量充足，避免过载）；无备份 → 临时启用应急链路或降级承载；命中人为 shutdown → 评估后 no shutdown 恢复；光模块老化但未到必须停业务更换的程度 → 可先 shutdown/no shutdown 复位清除CRC计数临时缓解（若已严重老化可能复位无效），或酌情将端口速率下调一档（如10G降1G）以降低误码率，两者均为过渡手段、需评估对带宽/断流的影响。
- 🔧 **根因处置（修复）**：光纤中断 → 抢修/更换光纤（更换前清洁光纤接头，排除灰尘导致的光衰）；光模块老化或硬件故障 → 准备同型号备件，在业务低谷期更换，若对端光模块参数也异常则同步更换；双工不匹配 → 改配置；线缆老化 → 换线。
- 🧭 **影响范围决策**：核心链路且有冗余 → 先切换恢复业务，再从容换件抢修；无冗余核心 → 边用应急链路承载边最快抢修；边缘或有实时热备 → 可评估后直接换件。（示例：核心光模块故障，先把受影响用户迁到正常链路，再择机停业务换模块）
- 🛡️ **预防措施（中长期，按需在改进建议中体现）**：建立光模块参数基线，定期采集偏置电流/温度预测剩余寿命；核心设备光模块备件按一定比例（如10%）储备，优先覆盖易老化型号；核查机房空调/设备风扇，确保光模块工作温度控制在合理范围（如40°C以下）；有条件时配置链路质量自动切换策略（CRC错误率超阈值自动切备）。

## 2. 网络设备故障

**故障现象**：网络设备整体不可达或部分功能异常，设备CPU/内存利用率异常升高，转发性能下降，下游业务大面积超时或中断。

**根因类型**：
- 交换机/路由器硬件故障（主板、风扇、电源模块损坏）
- 控制平面异常（BGP抖动、OSPF邻居断开、路由表抖动）
- 转发表溢出（MAC地址表、ARP表、FIB表超出设备容量）
- 设备过载（CPU利用率>90%、内存占用突破阈值）
- 设备软件缺陷（内存泄漏、进程崩溃、版本Bug）

**分析步骤**：
1. **告警识别**：接收设备syslog告警（BGP抖动、OSPF邻居断开、进程崩溃等）；或设备CPU/内存利用率阈值告警触发；或设备不可达告警。
2. **拓扑关联**：通过网络拓扑确认该设备在网络中的位置（核心层、汇聚层、接入层），关联下游受影响的业务服务和应用。
3. **性能指标分析**：查看设备CPU利用率、内存利用率、接口流量、转发包量等性能指标是否异常；检查转发表利用率是否接近或超过容量上限。
4. **根因判定**：
   - CPU突然升高且伴有路由抖动告警 → 控制平面异常
   - 转发表利用率超过阈值 → 转发表溢出
   - 设备不可达且无其他告警 → 硬件故障
   - CPU/内存持续高位且流量未异常 → 设备软件缺陷
5. **影响评估**：结合应用拓扑和流量指标，评估受影响业务范围，确认是否存在等价路由切换。

**⚑ 处置建议（先止血 · 后修复，按影响范围决策）**
- 🚑 **紧急预案（止血/降损）**：CPU/内存打满影响转发 → 先抑制诱因（限制或隔离异常流量、关闭引发风暴的端口、抑制广播），必要时切备/分流；转发表溢出 → 清理或扩表、分流；整机不可达 → 先区分真故障与管理面不可达，真宕机且有主备/双归 → 切至备用设备/路径恢复业务，主控故障 → 触发主备倒换。
- 🔧 **根因处置（修复）**：治理广播风暴源、稳定路由、扩容或升级设备、修复内存泄漏等软件缺陷（升级版本）；整机掉电 → 恢复供电/换电源；软件崩溃 → 重启/升级；主板或主控故障 → 换板。
- 🧭 **影响范围决策**：承载核心且性能濒临崩溃 → 先止血（隔离异常源/切备）保转发，再修根因；核心设备且有冗余 → 先切备恢复业务，再换件/抢修；无冗余核心 → 边应急边最快恢复；边缘设备或影响小 → 可直接检修处置。

## 3. 网络性能劣化

**故障现象**：网络延迟升高、丢包率增大、带宽利用率超过阈值，业务响应时间变慢但未完全中断，用户体验下降。

**根因类型**：
- 带宽瓶颈（链路利用率持续超过80%）
- 网络拥塞（缓存区溢出、队列堆积）
- 高延迟/抖动（网络延迟突增、抖动加大）
- 丢包率异常（接口丢包、TCP重传率升高）
- DNS解析异常（解析延迟、解析失败、DNS服务器不可用）
- QoS/限速策略不当（误限速、队列调度不合理导致特定流量被整形）
- 上层流量突发（业务突增、异常大流量超出链路承载）

**分析步骤**：
1. **告警识别**：接收带宽利用率阈值告警、延迟阈值告警、丢包率阈值告警，或TCP重传率异常告警，确认告警设备、接口、时间窗口。
2. **拓扑关联**：通过网络拓扑确认异常链路是否为业务主路径，是否存在备份路径；关联应用拓扑确认受影响的业务服务。
3. **性能指标分析**：查看告警设备及相关链路的带宽利用率、延迟、抖动、丢包率、TCP重传率等性能指标时序变化，确认异常开始时间和持续时间。
4. **根因判定**：
   - 带宽利用率持续超过80%且流量持续高位 → 带宽瓶颈
   - 延迟突增但带宽正常 + 队列丢弃上升 → 网络拥塞或队列堆积
   - 丢包率升高且CRC错误增加 → 链路质量问题
   - DNS解析延迟升高 → DNS服务异常
   - 命中限速/QoS变更 + 特定流量被整形 → QoS/限速策略不当
   - 流量基线大幅上偏 → 上层流量突发
5. **影响评估**：结合应用拓扑和业务性能指标，评估性能劣化对业务的实际影响程度。

**⚑ 处置建议（先止血 · 后修复，按影响范围决策）**
- 🚑 **紧急预案（止血/降损）**：带宽瓶颈/拥塞 → 临时启用 QoS 保障关键业务、限速非关键流量，或分流到备用链路；异常大流量 → 定位并抑制。
- 🔧 **根因处置（修复）**：扩容带宽、优化 QoS/队列、处理线缆质差（换线/清洁光口）、治理异常流量源。
- 🧭 **影响范围决策**：关键业务受阻 → 先按优先级保障/分流止血，再扩容优化；影响可容忍 → 直接扩容/优化。

## 4. 网络配置错误

**故障现象**：网络连通性异常（部分网段不可达）、流量异常（流量绕行、负载不均衡）、安全策略误拦，业务访问异常但设备硬件正常。

**根因类型**：
- 路由环路（静态路由配置错误导致报文循环转发）
- VLAN配置错误（端口VLAN ID不一致、Trunk允许VLAN缺失）
- ACL误配（访问控制列表规则错误拦截正常流量）
- MTU不匹配（链路两端MTU不一致导致大包丢弃）
- NAT配置异常（地址转换规则缺失或冲突）
- 路由重分发/前缀过滤错误（重分发引入非法路由、前缀列表误配导致路由黑洞）

**分析步骤**：
1. **告警识别**：接收路由抖动告警、BGP会话断开告警、或业务不可达的应用层告警；注意设备层可能无硬件告警，仅有路由协议事件。
2. **变更关联**：**重点步骤**——核查故障前是否有路由/ACL/VLAN/NAT配置变更，命中即高置信。
3. **拓扑关联**：通过网络拓扑检查异常路径上的设备连接关系，确认流量应走路径与实际路径是否一致；检查是否存在流量绕行现象。
4. **性能指标分析**：查看异常路径上的流量分布、延迟、丢包率；检查是否存在特定大小以上的包被丢弃（MTU问题特征）。
5. **根因判定**：
   - 配置变更命中 + 故障时间吻合 → 直接定位到该变更项
   - 路由抖动且流量绕行 → 路由环路或路由配置错误
   - 特定VLAN流量不通但其他VLAN正常 → VLAN配置错误
   - 特定源IP无法访问目标但其他源正常 → ACL误配
   - 大包丢弃但小包正常 → MTU不匹配
   - 出现路由黑洞/次优路由且命中策略变更 → 路由重分发/前缀过滤错误
6. **影响评估**：结合应用拓扑确认受影响的业务服务和用户端范围。

**⚑ 处置建议（先止血 · 后修复，按影响范围决策）**
- 🚑 **紧急预案（止血/降损）**：错误配置引发中断 → 立即回滚到上一版本配置（变更命中优先回滚）恢复业务。
- 🔧 **根因处置（修复）**：修正 VLAN/Trunk/ACL/MTU/NAT/路由策略等配置，复核后灰度下发。
- 🧭 **影响范围决策**：配置类几乎都先回滚止血（最快最稳），再离线核对修正后择机重新下发；仅当回滚不可行时在窗口内直接改配。

## 5. 网络安全事件

**故障现象**：网络流量异常激增、设备CPU突然升高、特定端口或协议流量异常，业务服务受到影响或安全告警触发。

**根因类型**：
- DDoS攻击（流量洪水、SYN Flood、UDP Flood等）
- ARP欺骗（网段内ARP欺骗导致流量劫持）
- 端口扫描（异常端口探测行为）
- 异常流量（数据泄露、未授权访问）
- 防火墙策略冲突（安全策略与业务需求冲突）

**分析步骤**：
1. **告警识别**：接收安全设备syslog告警（入侵检测、流量异常）、设备CPU异常告警、或特定协议流量阈值告警。
2. **拓扑关联**：通过网络拓扑确认受影响的网段和业务服务；检查是否有多个设备同时受到影响。
3. **性能指标分析**：查看异常设备的流量指标（入向/出向流量、包数、连接数），分析流量突增的时间点、源IP分布、目标端口分布。
4. **根因判定**：
   - 流量突增且源IP分布广泛、目标端口集中 → DDoS攻击
   - ARP表频繁变动且MAC地址泛洪 → ARP欺骗
   - 特定端口扫描流量异常 → 端口扫描
   - 防火墙日志显示策略拒绝但业务正常 → 防火墙策略冲突
5. **影响评估**：结合应用拓扑和业务指标，评估安全事件对业务的实际影响范围和程度。

**⚑ 处置建议（先止血 · 后修复，按影响范围决策）**
- 🚑 **紧急预案（止血/降损）**：DDoS → 启动清洗/限速/黑洞路由保护带宽与关键服务；ARP 欺骗/私接 → 隔离攻击/异常源端口；暴破/扫描 → 封禁源并加固访问。
- 🔧 **根因处置（修复）**：溯源攻击源并处置、部署防护策略（ACL/防火墙/Snooping/DAI）、加固弱口令与准入。
- 🧭 **影响范围决策**：安全事件一律先止损（清洗/隔离/封禁）保障业务与安全，再溯源加固；高风险封禁/割接需人工确认。

## 6. 路由协议震荡

**故障现象**：BGP/OSPF/ISIS邻居反复Up/Down，路由频繁重算，业务间歇中断或绕行，部分目的地不可达。

**根因类型**：
- 承载链路抖动/质差引发邻居flap（物理层传导）
- 协议定时器/认证/参数配置不当（hello/dead timer、MD5不一致）
- 路由表项/协议资源超限（前缀过多、内存不足）
- 路由策略/重分发错误导致黑洞或次优路由
- 邻居设备重启/不稳定（对端CPU高、软件异常）

**分析步骤**：
1. **告警识别**：接收BGP/OSPF/ISIS邻居状态变化、路由翻动告警。
2. **变更关联**：核查协议参数、策略、重分发配置是否近期变更。
3. **拓扑关联**：定位震荡邻居两端设备及承载链路，确认受影响路由域。
4. **性能指标分析**：对比邻居flap时刻与承载链路的CRC/光功率/丢包、与本端/对端CPU利用率的时序关系。
5. **根因判定**：
   - flap与链路CRC/光功率异常同步 → 链路质差传导
   - 命中定时器/认证变更 → 配置不当
   - 前缀数/协议内存接近上限 → 资源超限
   - 出现黑洞/次优且命中策略变更 → 重分发/策略错误
   - 对端CPU高或对端重启日志 → 邻居设备不稳定
6. **影响评估**：评估路由收敛频率、受影响业务路径与冗余。

**⚑ 处置建议（先止血 · 后修复，按影响范围决策）**
- 🚑 **紧急预案（止血/降损）**：邻居 flap 致业务绕行/中断 → 临时抑制震荡（调整/加大定时器、启用 dampening）、隔离质差链路、切至稳定路径。
- 🔧 **根因处置（修复）**：修复承载链路质差、纠正定时器/认证/策略配置、扩容协议资源、处置对端不稳定设备。
- 🧭 **影响范围决策**：核心路由动荡 → 先抑制/切稳定路径止血，再修根因；局部影响 → 直接修配置/链路。

## 7. 二层环路/广播风暴

**故障现象**：网段内大面积卡顿/不通，多设备CPU同时升高，广播/组播包速率激增，MAC地址频繁漂移。

**根因类型**：
- STP配置错误或失效（BPDU丢失、根桥异常）
- 物理成环（误接线、双上联未做聚合）
- 广播/组播风暴（异常主机、病毒、错误应用）
- MAC地址漂移（环路或双MAC）
- 接入侧设备/网卡故障引发环路

**分析步骤**：
1. **告警识别**：接收广播包速率阈值告警、MAC漂移告警、多设备CPU告警风暴。
2. **变更关联**：核查近期是否有接入侧布线/端口启用/STP参数变更。
3. **拓扑关联**：圈定异常广播域涉及的设备与端口范围。
4. **性能指标分析**：查看各端口广播/组播包速率、MAC表漂移记录、STP状态变化、相关端口CPU/流量。
5. **根因判定**：
   - 广播包速率激增 + MAC在多端口间漂移 → 二层环路
   - STP状态异常/根桥变更 + 命中变更 → STP配置错误/失效
   - 广播激增但无环路、源集中于个别主机 → 主机侧广播风暴
6. **影响评估**：评估广播域内受影响主机/业务范围，定位需隔离的端口。

**⚑ 处置建议（先止血 · 后修复，按影响范围决策）**
- 🚑 **紧急预案（止血/降损）**：立即定位并关闭成环/风暴源端口以隔离风暴，恢复 STP、抑制广播，尽快遏制扩散。
- 🔧 **根因处置（修复）**：拆除误接线并做聚合、修复 STP 配置、清除病毒/异常主机、处理漂移 MAC。
- 🧭 **影响范围决策**：环路影响面大且扩散快 → 第一时间隔离风暴源止血，再彻底整改拓扑/配置，不因等根因而放任风暴。

## 8. IP地址冲突

**故障现象**：网络时通时断、特定IP主机间歇不可达，ARP表中同一IP对应多个MAC，用户投诉网络不稳定。

**根因类型**：
- 静态IP配置冲突（人工配错、与已用地址重复）
- DHCP地址池与静态地址段重叠
- 非法接入设备私设IP
- ARP欺骗/MAC伪造导致的"伪冲突"
- 地址回收未释放（租约过期未回收，重复分配）

**分析步骤**：
1. **告警识别**：接收IP冲突告警、ARP表IP-MAC映射异常告警。
2. **变更关联**：核查近期是否有新设备上线、静态地址分配、DHCP地址池调整。
3. **拓扑关联**：通过ARP/MAC表定位冲突IP对应的多个MAC及其接入端口/设备。
4. **性能指标分析**：查看ARP表项变化频率、冲突时段的丢包/可达性、MAC漂移记录。
5. **根因判定**：
   - 冲突IP在DHCP池内 + 命中静态分配 → 池与静态重叠
   - 冲突MAC接入端口为非授权端口 → 非法私设IP
   - 同一IP对应MAC频繁切换且伴随网络中断 → ARP欺骗（转"网络安全事件"）
   - 命中地址分配变更 → 配置冲突
6. **影响评估**：定位受影响主机与端口，评估是否需端口隔离或地址回收。

**⚑ 处置建议（先止血 · 后修复，按影响范围决策）**
- 🚑 **紧急预案（止血/降损）**：冲突致业务中断 → 快速定位冲突双方（ARP/交换机 MAC 表），临时为关键端改址或隔离冲突/非法接入端口先恢复。
- 🔧 **根因处置（修复）**：规范静态分配、隔离 DHCP 与静态段、清除非法私设 IP、治理 ARP 欺骗、完善地址回收。
- 🧭 **影响范围决策**：冲突影响核心 → 先隔离冲突/非法源恢复，再规范地址管理；影响小则直接纠正配置。

## 9. DHCP服务故障

**故障现象**：新设备/重启设备无法获取IP地址，大面积终端无法上网。

**根因类型**：
- DHCP服务进程异常（服务宕机、无响应）
- 地址池耗尽（地址不足、租约回收不及时）
- 非法DHCP服务器抢答（客户端获取错误网关/DNS）
- DHCP中继（relay）配置错误（跨网段请求无法转发）
- 网络不通导致Discover/Offer丢失

**分析步骤**：
1. **告警识别**：接收DHCP服务状态告警、地址池使用率告警、终端获取地址失败告警。
2. **变更关联**：核查DHCP服务、地址池、relay配置近期变更。
3. **拓扑关联**：确认请求失败终端所在网段、对应relay设备与DHCP服务器路径。
4. **性能指标分析**：查看DHCP服务进程状态、地址池利用率、Discover/Offer/ACK报文计数、是否存在非授权DHCP应答源。
5. **根因判定**：
   - 服务进程异常/无响应 → DHCP服务故障
   - 地址池利用率100% → 地址池耗尽
   - 客户端获取到非法网关/DNS、存在未授权应答源 → 非法DHCP抢答（转"网络安全事件"）
   - 仅跨网段终端失败、本网段正常 → relay配置错误
6. **影响评估**：评估受影响网段终端数量与业务范围。

**⚑ 处置建议（先止血 · 后修复，按影响范围决策）**
- 🚑 **紧急预案（止血/降损）**：客户端拿不到地址 → 切备用 DHCP/临时静态地址保关键终端；有非法 DHCP 抢答 → 立即定位并隔离非法源端口。
- 🔧 **根因处置（修复）**：恢复/重启 DHCP 服务、扩地址池/回收租约、开启 DHCP Snooping 防非法、修正 relay 配置。
- 🧭 **影响范围决策**：面状影响 → 先切备/隔离非法源止血，再修服务与配置；单点影响可直接修。
