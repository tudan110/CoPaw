# IaaS层故障根因分析（6场景）

## 1. 硬件资源故障

**故障现象**：服务器硬件告警触发（CPU、内存、磁盘、电源等），上层虚拟机或应用出现异常，业务响应变慢或中断。

**根因类型**：
- CPU故障（CPU过热、核心故障、频率降频）
- 内存ECC错误（内存模块位翻转、不可纠正ECC错误）
- 磁盘坏道（SMART告警、磁盘读写错误率升高）
- 网卡故障（网卡掉线、网卡固件异常）
- 电源模块故障（电源冗余失效、电压异常）

**分析步骤**：
1. **告警识别**：接收IPMI/BMC上报的硬件告警（CPU过热、ECC错误、SMART告警、电源异常等），或操作系统syslog中的硬件错误信息（MCE、EDAC等）。
2. **拓扑关联**：通过IaaS拓扑确认该物理服务器上运行的虚拟机列表，关联应用拓扑确认受影响的业务服务。
3. **性能指标分析**：查看物理服务器的CPU温度、内存使用率、磁盘IOPS和延迟、网卡流量等性能指标是否异常；检查SMART指标（重新分配扇区计数、待处理扇区数等）。
4. **根因判定**：
   - CPU温度持续超过阈值且无业务负载对应 → CPU硬件故障
   - ECC错误计数持续增加 → 内存模块损坏
   - SMART重新分配扇区计数快速增长 → 磁盘坏道
   - 电源冗余状态变化 → 电源模块故障
5. **影响评估**：结合IaaS拓扑和应用拓扑，评估硬件故障影响的虚拟机和业务范围，确认是否已触发虚拟机迁移。

## 2. 虚拟化平台故障

**故障现象**：虚拟机异常迁移、状态变更、无法启动，Hypervisor平台告警，上层应用服务中断或性能下降。

**根因类型**：
- Hypervisor崩溃（内核Panic、内存泄漏、进程异常）
- VM异常迁移（实时迁移超时、迁移后状态异常）
- 资源超分（CPU、内存、磁盘IO超分导致性能下降）
- 调度失败（虚拟机无法调度到合适宿主机）
- 存储访问异常（共享存储响应延迟升高）

**分析步骤**：
1. **告警识别**：接收虚拟化平台的syslog告警（VM迁移事件、Hypervisor异常、调度失败等），或VM状态变更阈值告警（从Running变为Migrated/Error）。
2. **拓扑关联**：通过IaaS拓扑确认异常VM所在宿主机及同宿主机上的其他VM；关联应用拓扑确认受影响的业务服务。
3. **性能指标分析**：查看宿主机和VM的CPU利用率、内存利用率、磁盘IO延迟、网络IO等性能指标；检查宿主机资源超分比是否异常。
4. **根因判定**：
   - Hypervisor告警为内核Panic且宿主机上所有VM同时受影响 → Hypervisor崩溃
   - VM迁移后性能下降且新宿主机资源超分 → 资源超分
   - 调度日志显示无合适宿主机 → 调度失败
   - 存储IO延迟升高且共享存储指标异常 → 存储访问异常
5. **影响评估**：结合IaaS拓扑和应用拓扑，评估虚拟化故障影响的业务范围和恢复情况。

## 3. 存储系统故障

**故障现象**：存储IOPS异常、延迟升高、存储告警触发，上层数据库或应用出现IO等待、响应变慢。

**根因类型**：
- 磁盘阵列降级（RAID组降级、多盘故障）
- IO瓶颈（IOPS或吞吐量超过存储系统承载能力）
- 存储网络拥塞（FC/iSCSI网络延迟升高）
- LUN映射错误（LUN不可见、映射关系异常）
- 快照空间耗尽（快照占用空间超过阈值）
- 存储控制器故障/双活切换（控制器单边故障引发性能抖动）
- 写缓存电池（BBU）失效导致写缓存关闭（性能骤降的典型隐性原因）
- 多路径（multipath）故障/路径切换（路径丢失导致IO重分布）
- RAID重构（rebuild）期间性能下降

**分析步骤**：
1. **告警识别**：接收存储设备syslog告警（RAID降级、磁盘故障、LUN异常、控制器/路径事件）或存储性能阈值告警（IO延迟、IOPS异常）。
2. **拓扑关联**：通过IaaS拓扑确认异常存储挂载的VM和应用；关联网络拓扑检查存储网络链路状态。
3. **性能指标分析**：查看存储系统的IOPS、吞吐量、IO延迟、队列深度等性能指标；检查存储池利用率、快照空间、控制器/路径状态。
4. **根因判定**：
   - RAID状态为Degraded且磁盘故障告警 → 磁盘阵列降级
   - 写延迟突增且BBU/缓存状态告警 → 写缓存关闭（BBU失效）
   - 控制器告警 + IO在双控间切换 → 控制器故障/双活切换
   - 路径数减少 + IO抖动 → 多路径故障
   - IOPS持续超过承载能力且队列深度升高 → IO瓶颈
   - 存储网络延迟升高且网络设备有告警 → 存储网络拥塞
   - LUN不可见且映射关系异常 → LUN映射错误
   - 降级且重构进行中、性能阶段性下降 → RAID重构影响
5. **影响评估**：结合IaaS拓扑和应用拓扑，评估存储故障影响的数据库、应用和业务范围。

## 4. 操作系统故障

**故障现象**：操作系统告警触发（内核错误、文件系统异常等），进程异常退出，服务响应变慢或中断。

**根因类型**：
- 内核Panic（内核Bug、驱动缺陷、硬件不兼容）
- 文件系统损坏（文件系统只读、文件系统一致性破坏）
- 驱动异常（驱动版本不兼容、驱动加载失败）
- 系统进程僵死（D状态进程、不可中断的睡眠状态）
- 内核参数不当（内核参数调优不当导致性能问题）
- 软中断/中断风暴（高si、网卡中断不均衡导致单核CPU占满）

**分析步骤**：
1. **告警识别**：接收操作系统syslog告警（kernel panic、oom-killer、文件系统错误、hung task等），或进程状态阈值告警（僵死进程、服务不可用）。
2. **变更关联**：核查近期内核/驱动升级、内核参数调整记录。
3. **拓扑关联**：通过IaaS拓扑确认异常主机上的VM和应用；关联应用拓扑确认受影响的业务服务。
4. **性能指标分析**：查看系统负载、内存使用率、IO等待、进程状态、软中断占比等性能指标；检查是否有D状态进程（不可中断睡眠状态）。
5. **根因判定**：
   - syslog显示kernel panic且系统重启 → 内核Panic
   - 文件系统报只读或一致性错误 → 文件系统损坏
   - 命中驱动/内核升级 + 加载失败 → 驱动异常
   - 进程处于D状态且不可中断 + IO等待高 → 系统进程僵死（常与存储IO慢联动）
   - si占比异常高 → 软中断/中断风暴
6. **影响评估**：结合IaaS拓扑和应用拓扑，评估操作系统故障影响的业务范围和恢复情况。

## 5. 资源耗尽

**故障现象**：系统资源使用率达到上限，新请求无法处理，服务响应变慢或拒绝服务，OOM等告警触发。

**根因类型**：
- CPU饱和（CPU利用率持续100%）
- 内存耗尽（OOM Killer触发、内存分配失败）
- 磁盘空间满（磁盘使用率超过95%）
- 文件描述符耗尽（进程无法打开新文件）
- 连接数超限（TCP连接数超过系统配置上限）
- inode耗尽（磁盘有空间但inode用尽——海量小文件场景）
- 临时端口（ephemeral port）耗尽（高并发短连接导致大量TIME_WAIT）
- swap耗尽（伴随严重抖动/卡顿，内存严重不足的延伸）
- PID耗尽（进程/线程泄漏导致无法创建新进程）

**分析步骤**：
1. **告警识别**：接收资源阈值告警（CPU利用率、内存使用率、磁盘使用率、inode、连接数超过阈值），或syslog中的OOM Killer告警、连接拒绝告警。
2. **拓扑关联**：通过IaaS拓扑确认影响的VM和应用；关联应用拓扑确认受影响的业务服务链路。
3. **性能指标分析**：查看系统资源使用率时序变化，确认资源耗尽的时间点和持续时间；检查是否有特定进程占用大量资源；分别检查磁盘空间与inode、连接数与端口占用。
4. **根因判定**：
   - CPU利用率持续100%且无异常进程 → 业务负载超过容量
   - OOM Killer触发且内存使用率超过95% → 内存耗尽
   - 磁盘使用率超过95% → 磁盘空间满
   - 磁盘空间未满但inode用尽 → inode耗尽
   - 文件描述符计数接近系统上限 → 文件描述符耗尽
   - TCP连接数超过配置上限 → 连接数超限
   - 本地端口耗尽 + 大量TIME_WAIT → 临时端口耗尽
   - swap使用率高 + 抖动剧烈 → swap耗尽
   - 进程/线程数持续增长 → PID耗尽（泄漏）
5. **影响评估**：结合应用拓扑和业务指标，评估资源耗尽对业务的影响范围和程度。

## 6. 时钟同步异常

**故障现象**：主机时间与基准源偏差过大或跳变，引发证书/令牌校验失败、日志时序错乱、分布式一致性异常、数据库主从/集群仲裁异常。

**根因类型**：
- NTP源不可达（上游时钟服务器故障或网络不通）
- 时钟漂移/跳变（晶振问题、虚拟化宿主时钟传导）
- NTP配置错误（多源冲突、未配置可信源）
- 大幅step校正引发业务异常

> 数据基础：基于OS Syslog中ntpd/chronyd同步丢失/校正消息。精确偏移量分析需补充时钟偏移指标，当前以syslog事件为主。

**分析步骤**：
1. **告警识别**：接收OS syslog中ntpd/chronyd同步丢失、时间step校正消息。
2. **变更关联**：核查NTP配置变更、虚拟化平台时钟相关变更。
3. **拓扑关联**：确认共用同一上游NTP源的主机范围（判断是单机还是面状）。
4. **性能指标分析**：查看同步状态、校正事件频率，结合关联业务的"校验失败/一致性异常"告警时序。
5. **根因判定**：
   - 多主机同时失同步、共用同一源 → NTP源不可达（面状）
   - 单机频繁step校正 → 本机时钟漂移
   - 命中NTP配置变更 → 配置错误
6. **影响评估**：评估受时间敏感型业务（鉴权、交易、分布式事务）影响范围。
