# PaaS层故障根因分析（7场景）

## 1. 容器编排故障

**故障现象**：Pod状态异常（CrashLoopBackOff、OOMKilled、ImagePullBackOff等），节点NotReady，HPA异常扩缩容，业务服务中断或响应变慢。

**根因类型**：
- Pod CrashLoopBackOff（应用启动失败、健康检查不通过、配置错误）
- OOMKilled（容器内存超过限制被杀死）
- 镜像拉取失败（镜像仓库不可达、镜像不存在、认证失败）
- 节点NotReady（kubelet异常、节点资源不足、网络不通）
- HPA异常扩缩容（指标采集异常、扩缩容策略不当）

**分析步骤**：
1. **告警识别**：接收容器编排平台的告警（Pod状态变更、OOMKilled、CrashLoopBackOff、节点NotReady等），或应用层服务不可用告警。
2. **拓扑关联**：通过应用拓扑确认异常Pod对应的业务服务；检查同一Deployment下其他Pod的状态；关联IaaS拓扑确认节点所在宿主机状态。
3. **性能指标分析**：查看Pod的CPU/内存使用率、重启次数、容器状态；检查节点资源使用率和状态；检查HPA扩缩容指标和当前副本数。
4. **根因判定**：
   - Pod反复重启且日志显示启动失败 → CrashLoopBackOff
   - Pod被OOMKilled且内存使用率超过限制 → 内存不足
   - 镜像拉取失败告警 → 镜像仓库问题
   - 节点NotReady且kubelet异常 → 节点故障
   - HPA扩缩容异常且指标采集异常 → HPA配置问题
5. **影响评估**：结合应用拓扑和业务指标，评估容器故障影响的业务范围和恢复情况。

**⚑ 处置建议（先止血 · 后修复，按影响范围决策）**
- 🚑 **紧急预案（止血/降损）**：Pod 崩溃/重启 → 回滚上一稳定版本、扩副本到健康节点；节点 NotReady → cordon/drain 驱逐并调度到健康节点；镜像拉取失败 → 切换可用镜像仓库或回退可用镜像版本；HPA 异常扩缩容 → 临时固定副本数、暂停自动扩缩容。
- 🔧 **根因处置（修复）**：修复镜像/资源 limit/存储卷、消除 OOM、修复健康检查与启动配置、恢复节点 kubelet 与资源水位、修正 HPA 指标采集与扩缩容策略。
- 🧭 **影响范围决策**：核心工作负载 → 先回滚/扩副本/驱逐止血，再修组件根因；有多副本可自愈则观察后处置。

## 2. 中间件服务故障

**故障现象**：消息队列积压、连接池耗尽、线程池满、服务注册异常，上层应用出现超时、降级或中断。

**根因类型**：
- 消息队列积压（消费速度不足、消费者异常、分区不均衡）
- 连接池耗尽（连接泄漏、最大连接数不足、超时配置不当）
- 线程池满（线程泄漏、最大线程数不足、慢调用阻塞）
- 注册中心异常（服务注册失败、心跳丢失、注册中心不可用）
- 网关限流（流量超过网关限制、熔断触发）

**分析步骤**：
1. **告警识别**：接收中间件的阈值告警（队列积压、连接池使用率、线程池使用率超过阈值），或syslog中的服务注册异常、网关限流告警。
2. **拓扑关联**：通过应用拓扑确认依赖该中间件的业务服务；关联IaaS拓扑确认中间件所在节点的资源状态。
3. **性能指标分析**：查看中间件的队列深度、消费延迟、连接池活跃数、线程池活跃数、吞吐量等性能指标。
4. **根因判定**：
   - 队列深度持续增长且消费延迟升高 → 消息队列积压
   - 连接池活跃数接近最大值且等待队列增长 → 连接池耗尽
   - 线程池活跃数达到上限且请求排队 → 线程池满
   - 服务注册丢失且心跳异常 → 注册中心异常
   - 网关限流告警触发且流量超过限制 → 网关限流
5. **影响评估**：结合应用拓扑和业务指标，评估中间件故障影响的业务范围和程度。

**⚑ 处置建议（先止血 · 后修复，按影响范围决策）**
- 🚑 **紧急预案（止血/降损）**：MQ 积压 → 扩消费者/临时扩分区，必要时对非关键消息降级；连接池/线程池满 → 提上限、熔断慢依赖；注册中心异常 → 切集群其它节点；网关限流误触发 → 调阈值放行关键业务。
- 🔧 **根因处置（修复）**：修复消费者性能、治理连接/线程泄漏、优化超时与限流、恢复注册中心与集群。
- 🧭 **影响范围决策**：核心链路阻塞 → 先扩容/熔断/切节点止血，再修泄漏与配置根因；积压可追赶则直接优化消费。

## 3. 服务网格故障

**故障现象**：服务网格Sidecar异常、流量路由错误、mTLS证书过期、熔断器触发，业务服务间调用异常。

**根因类型**：
- Sidecar注入失败（自动注入策略异常、资源不足）
- mTLS证书过期（证书自动轮转失败、证书链不完整）
- 流量路由错误（VirtualService/DestinationRule配置错误）
- 熔断器误触发（熔断阈值配置不当、慢调用导致误触发）
- Envoy异常（Envoy进程崩溃、配置下发失败）

**分析步骤**：
1. **告警识别**：接收服务网格控制面板的告警（Sidecar注入失败、证书过期、熔断触发等），或应用层服务间调用失败告警。
2. **拓扑关联**：通过应用拓扑确认异常服务的上下游调用关系；检查是否有多个服务同时受到影响。
3. **性能指标分析**：查看服务网格的调用成功率、延迟分布、熔断器状态、Envoy资源使用率等性能指标。
4. **根因判定**：
   - Sidecar注入失败且Pod无Sidecar容器 → Sidecar注入异常
   - mTLS握手失败且证书过期告警 → 证书过期
   - 流量路由与预期不一致且VirtualService配置变更 → 流量路由错误
   - 熔断器触发且延迟阈值过低 → 熔断器误触发
   - Envoy进程崩溃且配置下发失败 → Envoy异常
5. **影响评估**：结合应用拓扑和业务指标，评估服务网格故障影响的业务范围和程度。

**⚑ 处置建议（先止血 · 后修复，按影响范围决策）**
- 🚑 **紧急预案（止血/降损）**：流量路由错误 → 回滚 VirtualService/DestinationRule 到上一稳定配置；熔断误触发 → 临时放宽熔断阈值恢复调用；mTLS 证书过期 → 紧急续期，必要时临时切换 PERMISSIVE 模式保通；Sidecar/Envoy 异常 → 重建异常 Pod 使 Sidecar 重新注入，或临时对受影响服务绕行网格直连。
- 🔧 **根因处置（修复）**：修复自动注入策略与资源配额、恢复证书自动轮转与证书链、修正路由配置并纳入变更校验、按真实延迟基线调优熔断阈值、修复 Envoy 配置下发链路。
- 🧭 **影响范围决策**：多服务调用链同时受影响（证书/控制面级故障）→ 先回滚配置/放宽策略全局止血，再修控制面根因；仅单服务 Sidecar 异常则重建该 Pod 即可，观察后处置。

## 4. 数据库与缓存故障

**故障现象**：数据库慢查询、死锁、主从切换异常、连接数打满，缓存穿透/雪崩/击穿，业务数据访问异常。

**根因类型**：
- 慢查询（缺失索引、查询计划不优、大事务）
- 死锁（多事务循环等待、锁顺序不一致）
- 长事务/锁等待（非死锁的锁阻塞）
- 主从切换失败（复制延迟、数据不一致、切换脚本异常）
- 复制中断（复制线程停止）/主从延迟
- 连接数超限（最大连接数不足、连接泄漏、连接打满）
- 事务日志/binlog/redo空间满（写阻塞、库不可写）
- 统计信息过期导致执行计划劣化
- 表损坏/崩溃（查询报错、表不可访问）
- 数据库OOM（进程被kill、内存配置不当）
- 缓存穿透（查询不存在的key直击DB）
- 缓存雪崩（大量key同时过期/缓存宕机）
- 缓存击穿（热点key过期瞬间高并发回源）

**分析步骤**：
1. **告警识别**：接收数据库/缓存的阈值告警（慢查询、死锁、连接数、主从切换、复制状态、内存等），或应用层数据访问异常告警。
2. **变更关联**：核查SQL发布、索引变更、参数调整、缓存策略变更。
3. **拓扑关联**：通过应用拓扑确认依赖该数据库/缓存的业务服务；关联IaaS拓扑确认节点资源（含存储IO）。
4. **性能指标分析**：查看QPS、响应延迟、慢查询/死锁计数、活跃连接数、复制延迟与线程状态、锁等待、缓存命中率、内存使用、日志空间。
5. **根因判定**：
   - 慢查询计数升高 + 延迟增大 → 慢查询（结合执行计划/统计信息判断是否计划劣化）
   - 死锁检测告警 → 死锁；大量会话锁等待但无死锁 → 长事务/锁等待
   - 复制线程停止/报错 → 复制中断；仅延迟升高 → 复制延迟
   - 主从切换事件 + 复制异常 → 主从切换异常
   - 活跃连接达上限 → 连接数超限
   - 日志/binlog空间满 + 写阻塞 → 事务日志空间满
   - 内存超限 + 进程被kill → 数据库OOM
   - 缓存命中率突降 + DB压力骤增：命中"不存在key集中"→穿透；"大批key同时失效/实例宕机"→雪崩；"单热点key失效瞬间"→击穿
6. **影响评估**：结合应用拓扑和业务指标，评估数据库/缓存故障影响的业务范围和程度。

**⚑ 处置建议（先止血 · 后修复，按影响范围决策）**
- 🚑 **紧急预案（止血/降损）**：慢查询/锁 → 先 kill 阻塞大事务/慢 SQL、限流写入；连接打满 → 释放空闲连接、提上限、切读库；主从异常 → 按预案切换到健康副本；缓存雪崩/穿透 → 加空值/随机过期/限流回源、临时扩缓存。
- 🔧 **根因处置（修复）**：补索引/优化 SQL 与执行计划、消除死锁与长事务、修复复制、扩容连接、清理日志空间、修复缓存策略（防穿透/雪崩/击穿）。
- 🧭 **影响范围决策**：核心库濒临不可用 → 先止血（kill 阻塞/切副本/限流/护缓存）恢复访问，再优化根因；只读副本可承接则先切读。（高风险 kill/切主需人工确认）

## 5. 配置与证书故障

**故障现象**：配置变更后服务异常、证书过期导致服务不可用、密钥泄露告警，业务服务访问异常。

**根因类型**：
- 配置变更错误（配置发布引入错误参数、回滚失败）
- 密钥泄露（密钥被提交到代码仓库、未加密存储）
- 证书过期（TLS证书未及时续期、自动续期失败）
- 环境变量缺失（配置未同步到所有环境）
- Feature Flag误配（功能开关配置错误导致服务异常）

**分析步骤**：
1. **告警识别**：接收配置变更告警、证书过期告警、密钥泄露告警，或服务启动失败的应用层告警。
2. **拓扑关联**：通过应用拓扑确认受影响的服务和业务；检查配置变更的时间点与故障发生时间的关联性。
3. **性能指标分析**：查看服务错误率、响应延迟是否在配置变更后异常；检查TLS握手失败率是否升高。
4. **根因判定**：
   - 服务异常发生在配置变更后且回滚后恢复 → 配置变更错误
   - TLS握手失败且证书过期告警 → 证书过期
   - 服务启动失败且环境变量缺失 → 环境变量缺失
   - Feature Flag变更后服务异常 → Feature Flag误配
5. **影响评估**：结合应用拓扑和业务指标，评估配置/证书故障影响的业务范围和程度。

**⚑ 处置建议（先止血 · 后修复，按影响范围决策）**
- 🚑 **紧急预案（止血/降损）**：配置变更错误/Feature Flag 误配 → 立即回滚到上一稳定配置版本或关闭开关；证书过期 → 紧急续期或临时切换可用通道；密钥泄露 → 立即吊销并轮换密钥、封堵异常访问来源；环境变量缺失 → 紧急补配并重启受影响服务。
- 🔧 **根因处置（修复）**：修复配置发布流水线与发布前校验/灰度机制、补齐多环境配置同步、更新证书并加到期监控与自动续期、清理泄露密钥并接入密钥管理系统、规范 Feature Flag 变更审批。
- 🧭 **影响范围决策**：故障时间与变更时间强关联 → 一律先回滚止血再排查根因；证书类先续期恢复访问再排查签发/轮转链路；密钥泄露涉及安全，止血（吊销轮换）优先级最高。

## 6. 云主机/计算资源故障

**故障现象**：云主机无响应、性能不稳定、被驱逐，云盘性能受限或可用区整体异常，承载业务受影响。

**根因类型**：
- 云主机无响应（无法SSH/ping、控制台无输出）
- 云主机性能争抢（CPU Steal Time/CPU Ready高）
- 云主机被驱逐（节点资源不足导致实例被kill）
- 云盘IOPS/吞吐达到上限（IO限流、应用变慢）
- 可用区故障（单可用区实例批量不可用）

**分析步骤**：
1. **告警识别**：接收云主机状态、云盘性能、节点驱逐、可用区事件告警。
2. **变更关联**：核查近期实例规格变更、迁移、扩缩容、云网络配置变更。
3. **拓扑关联**：确认实例所在宿主/节点/可用区及承载业务，关联同可用区其他实例。
4. **性能指标分析**：查看实例CPU/内存/网络、Steal Time/CPU Ready、云盘IOPS/吞吐与限额、节点资源水位、可用区健康。
5. **根因判定**：
   - 实例无响应 + 控制台无输出 → 云主机宕机/卡死
   - Steal Time高 + 同宿主负载高 → 性能争抢
   - 实例被kill + 节点资源不足 → 被驱逐
   - 云盘IOPS触顶 + IO延迟升高 → 云盘性能达上限
   - 同可用区多实例同时不可用 → 可用区故障
6. **影响评估**：评估受影响实例与业务，判断是否需跨可用区切换/升配/扩容。

**⚑ 处置建议（先止血 · 后修复，按影响范围决策）**
- 🚑 **紧急预案（止血/降损）**：云主机无响应/被驱逐且有集群 → 迁移/重建实例到健康节点；性能争抢 → 迁移或升配；云盘 IO 触顶 → 限流/换更高规格盘；可用区故障 → 切换到其它可用区。
- 🔧 **根因处置（修复）**：重建/升配实例、消除同宿主争抢、扩云盘 IOPS、加固跨 AZ 容灾。
- 🧭 **影响范围决策**：承载核心且多副本/跨 AZ → 先切换/迁移恢复业务，再处置故障实例；单实例核心需边应急边重建。

## 7. 负载均衡/网关故障

**故障现象**：流量无法正确转发、连接超时、HTTPS访问报错或大量请求被拒，业务入口不稳定。

**根因类型**：
- 后端健康检查失败（流量不转发到故障后端，或后端全摘）
- 负载均衡器过载（连接数/CPU高、连接超时、丢包）
- 会话保持异常（用户频繁登出、状态丢失）
- SSL证书过期（HTTPS无法访问、浏览器报错）
- 限流触发（大量请求被拒绝429）
- VIP漂移/主备切换异常

**分析步骤**：
1. **告警识别**：接收LB/网关健康检查、连接数、限流命中、证书有效期、VIP状态告警。
2. **变更关联**：核查近期LB配置、后端节点、健康检查、证书、限流阈值变更。
3. **拓扑关联**：确认LB后端节点池、VIP及承载业务，关联后端服务健康。
4. **性能指标分析**：查看后端健康状态、LB连接数/CPU、会话保持命中、证书剩余有效期、限流命中次数、VIP状态。
5. **根因判定**：
   - 后端健康检查失败/全摘 → 后端服务故障或健康检查配置问题
   - LB连接数/CPU触顶 + 超时 → LB过载
   - 用户状态频繁丢失 + 会话保持配置异常 → 会话保持问题
   - HTTPS报错 + 证书过期 → SSL证书过期
   - 大量429 + 限流命中激增 → 限流触发
   - VIP异常切换 → VIP漂移/主备问题
6. **影响评估**：评估入口不可用/降级对业务与用户的影响范围。

**⚑ 处置建议（先止血 · 后修复，按影响范围决策）**
- 🚑 **紧急预案（止血/降损）**：后端全摘/LB 过载 → 摘除故障后端、扩后端或扩 LB，必要时切备 VIP；证书过期 → 紧急续期或临时切内网 HTTP 通道；限流误触发 → 调阈值放行关键业务。
- 🔧 **根因处置（修复）**：修复健康检查与后端、扩容 LB、修会话保持、更新证书并加到期监控、优化限流策略、修 VIP 漂移。
- 🧭 **影响范围决策**：入口级故障影响面最大 → 先切备/扩容/摘故障后端止血，再修根因；证书类先续期恢复再排查签发链路。
