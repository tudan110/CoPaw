# 跨层复合故障根因分析（4场景）

## 1. 级联故障

**故障现象**：单个组件故障导致多个上游服务异常，故障波及范围远超单点，形成雪崩效应。

**根因类型**：
- 雪崩效应（单点故障触发超时重试风暴，耗尽上游资源）
- 故障扩散（共享依赖故障导致多条业务线受影响）
- 依赖链断裂（核心服务不可用导致整条业务链中断）
- 资源争抢（多个服务竞争同一资源导致全局性能下降）

**分析步骤**：
1. **告警识别**：接收多个服务同时报告异常的告警风暴，或多个阈值告警同时触发；识别告警的时间关联性和空间关联性。
2. **拓扑关联**：通过应用拓扑和网络拓扑追踪故障传播路径，确认故障源头和扩散范围；检查是否存在共享依赖节点。
3. **性能指标分析**：查看各层服务的响应延迟、错误率、资源使用率等指标的时序变化，确认故障传播的时间顺序。
4. **根因判定**：
   - 单点故障后上游服务超时重试量激增 → 雪崩效应
   - 多个不相关业务同时受影响且共享同一依赖 → 共享依赖故障扩散
   - 核心服务不可用且整条链路中断 → 依赖链断裂
   - 多个服务资源使用率同时升高且存在资源竞争 → 资源争抢
5. **影响评估**：结合全层拓扑和业务指标，评估级联故障影响的业务范围和程度。

## 2. 网络-应用联合故障

**故障现象**：网络异常导致应用服务调用异常，或应用异常放大网络问题，表现为网络和应用同时异常。

**根因类型**：
- 网络抖动导致超时重试风暴（网络不稳定触发应用重试机制）
- DNS故障导致服务发现失败（DNS解析异常导致服务注册失败）
- 网络分区故障导致脑裂（网络分区导致集群脑裂）
- 网络延迟升高导致服务调用超时（网络问题被应用超时放大）

**分析步骤**：
1. **告警识别**：同时接收网络层告警（延迟升高、丢包、DNS异常）和应用层告警（服务调用失败、超时），确认两层告警的时间关联性。
2. **拓扑关联**：通过网络拓扑和应用拓扑的交叉关联，确认网络异常路径与应用异常服务的对应关系。
3. **性能指标分析**：对比网络延迟/丢包率与应用响应延迟/错误率的时序关系，确认因果时序。
4. **根因判定**：
   - 网络抖动在先且应用重试量激增在后 → 网络抖动导致重试风暴
   - DNS解析异常且服务注册失败 → DNS故障导致服务发现失败
   - 网络分区且集群脑裂 → 网络分区导致脑裂
   - 网络延迟升高在先且应用超时在后 → 网络延迟导致服务超时
5. **影响评估**：结合全层拓扑和业务指标，评估联合故障影响的业务范围和程度。

## 3. IaaS-PaaS联合故障

**故障现象**：IaaS层资源异常导致PaaS层服务异常，或PaaS层异常放大IaaS层问题，表现为基础设施和平台服务同时异常。

**根因类型**：
- 宿主机故障导致Pod批量驱逐（宿主机Down导致上面所有Pod不可用）
- 存储IO慢导致数据库性能劣化（存储层问题影响数据库性能）
- 网络IO异常导致服务网格不稳定（网络层问题影响服务网格）
- 资源超分导致容器调度异常（宿主机资源超分影响容器调度）

**分析步骤**：
1. **告警识别**：同时接收IaaS层告警（宿主机Down、存储IO异常、网络IO异常）和PaaS层告警（Pod驱逐、数据库慢查询、服务网格不稳定），确认两层告警的时间关联性。
2. **拓扑关联**：通过IaaS拓扑和应用拓扑的交叉关联，确认异常宿主机上运行的Pod和业务服务。
3. **性能指标分析**：对比IaaS层资源指标（宿主机CPU/内存/磁盘IO/网络IO）与PaaS层服务指标（Pod状态、数据库响应、服务网格延迟）的时序关系。
4. **根因判定**：
   - 宿主机Down且上面Pod全部不可用 → 宿主机故障导致Pod批量驱逐
   - 存储IO延迟升高且数据库慢查询增多 → 存储IO慢导致数据库性能劣化
   - 网络IO异常且服务网格不稳定 → 网络IO异常导致服务网格不稳定
   - 宿主机资源超分且容器调度失败 → 资源超分导致容器调度异常
5. **影响评估**：结合全层拓扑和业务指标，评估联合故障影响的业务范围和程度。

## 4. 全链路退化

**故障现象**：多个节点同时性能下降，但未达到告警阈值，业务整体变慢但未完全中断，用户体验明显下降。

**根因类型**：
- 多节点性能下降叠加（各层小问题累积导致全链路退化）
- 容量规划不足（流量增长超过各层容量规划）
- 流量突增叠加资源不足（突发流量叠加已有资源紧张）
- 全局性配置偏差（多层配置不优导致整体性能下降）

**分析步骤**：
1. **告警识别**：接收多层性能指标轻度异常告警（未达到严重告警但持续异常），或业务层用户体验指标异常告警。
2. **拓扑关联**：通过全层拓扑（网络+IaaS+PaaS+应用）检查各层节点的性能状态，确认退化的层次和位置。
3. **性能指标分析**：查看各层节点的性能指标时序变化，分析哪些节点退化最严重；检查流量模式是否有变化。
4. **根因判定**：
   - 各层小异常累积且单点均未超过严重阈值 → 多节点性能下降叠加
   - 流量持续增长且各层资源接近上限 → 容量规划不足
   - 突发流量叠加已有资源紧张 → 流量突增叠加资源不足
   - 各层配置均有优化空间且全局性能下降 → 全局性配置偏差
5. **影响评估**：结合全层拓扑和业务指标，评估全链路退化影响的业务范围和程度。

## 分析方法论

### 五步分析法（统一流程）

| 步骤 | 名称 | 核心内容 |
|------|------|----------|
| 步骤1 | 告警识别 | 从syslog告警、阈值告警中识别故障事件，确认告警类型、对象、时间，形成故障初始线索 |
| 步骤2 | 拓扑关联 | 通过网络拓扑、IaaS拓扑、应用拓扑确定故障对象位置，关联上下游依赖，确认影响范围 |
| 步骤3 | 性能指标分析 | 查看相关对象的性能指标时序变化，确认异常开始时间、持续时间和严重程度 |
| 步骤4 | 根因判定 | 综合告警、拓扑、指标，通过多维度交叉验证，精准定位根因 |
| 步骤5 | 影响评估 | 结合拓扑和业务指标，评估故障对业务的实际影响范围和程度 |

### 关键分析技术

| 技术方法 | 适用场景 | 数据依赖 |
|----------|----------|----------|
| 拓扑关联分析 | 故障定位、影响范围分析 | 网络拓扑、IaaS拓扑、应用拓扑 |
| 时序相关性分析 | 因果时序验证、故障传播路径分析 | 告警时间戳、性能指标时序数据 |
| 阈值异常检测 | 性能劣化、资源耗尽等场景 | 性能指标时序数据、阈值配置 |
| 告警风暴关联 | 级联故障、多服务同时异常 | 同时间窗内的多条告警 |
| 因果推理 | 复杂故障的根因定位 | 告警+指标+拓扑的融合数据 |
