# Page Navigator(门户页面导航)

把用户【明确的页面 / 导航诉求】解析为门户前端的路由(如
`/ops/xj/results`),并产出一段**结构化跳转指令**,由调用本 agent 的
前端小助手解析后执行 `router.push` 跳转。

## 什么时候用本技能(必须是"明确的页面/导航意图")

- 用户话里点到了"**页面 / 菜单 / 在哪里 / 怎么进 / 怎么找到 / 跳转 /
  导航 / 带我去**"。
- 例:
  - "巡检结果报表页面在哪?" → 跳转
  - "打开自动巡检的结果报表页面" → 跳转
  - "跳转到工单统计页面" / "带我去资产台账页面" → 跳转
  - "IP地址管理在哪个菜单?" → 跳转

## 什么时候【不要】用本技能(默认让业务技能优先)

- 用户只是想看数据 / 结果、没点出"页面 / 导航" —— 交给业务技能:
  - "看巡检结果报表" / "我想看巡检结果报表" → 交给 `inspection-analyst`
    出报表数据,**不要跳转**
  - "我想看工单统计" → 交给工单技能
  - "查一下告警" / "巡检一下数据库" → 交给对应数据技能
- 一句话:**含糊 = 业务优先;明确说"页面 / 在哪 / 跳转 / 打开…页面" =
  才跳转。**

## 边界

- 不负责回答页面里的业务数据,只负责"带路"。
- 真正的跳转动作在前端执行,本技能只产出路由 + 指令;不要声称自己
  "已经打开了"页面,而是"正在为您打开"。
- 不要泄露接口 token。

## 用法

唯一入口是 `scripts/find_page.py`,传入用户的原话或页面关键词:

```bash
cd skills/page-navigator
python3 scripts/find_page.py "巡检结果报表" --output agent
```

脚本会拉取门户菜单路由(带缓存)、做语义匹配,并按置信度返回三种
`mode` 之一。请严格按下面的方式处理:

### 1) mode = navigate(单个高置信命中)

脚本 `--output agent` 已经给出"正在为您打开「…」"的话术 **以及**一段
` ```qwenpaw:navigate ``` ` 指令块。请把脚本输出**原样**回复给用户,
**指令块必须逐字保留、不要改写 path**。前端会解析它并跳转。

示例输出:

````
好的,正在为您打开「运维中心 / 自动巡检 / 结果报表」。

```qwenpaw:navigate
{"path": "/ops/xj/results", "title": "结果报表", "breadcrumb": "运维中心 / 自动巡检 / 结果报表"}
```
````

### 2) mode = disambiguate(多个候选 / 置信度接近)

脚本会列出带编号和面包屑的候选。把候选列表回复给用户,请他用编号或
页面名称确认。用户确认后,用确认后的页面名再调用一次脚本(或对该候选
路径调用 `--output directive`)拿到指令块再回复。

### 3) mode = not_found(没匹配到)

告知用户没找到,并把脚本给出的"接近的页面"作为建议,请用户换个说法或
给更完整的页面名称。

## 输出模式

- `--output agent`(默认):给用户看的人话 + 指令块。
- `--output json`:完整候选结构(含 score),调试用。
- `--output directive`:仅打印指令块。
- `--refresh`:忽略缓存强制刷新菜单(菜单很久没更新且怀疑过期时用)。

## 配置

菜单接口与告警/监控同属 INOE 后端,**优先复用共享 `secrets/inoe.env`
里的 `INOE_API_BASE_URL` / `INOE_API_TOKEN`**;未配置时回退本技能目录
`.env` 或同名环境变量。详见 `.env.example` 与 `references/navigate-contract.md`。
