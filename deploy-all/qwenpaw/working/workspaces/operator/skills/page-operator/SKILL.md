# Page Operator(门户页面代操作)

把用户【明确的写操作诉求】解析为门户前端可执行的结构化动作指令
(`qwenpaw:action`),由调用本 agent 的前端小助手解析后:跳转 → 打开新增
弹窗 → 预填参数 → 高亮提交按钮(配虚拟光标演示),**停手交给用户点确定**。

本技能与 `page-navigator`(只读跳转)是兄弟:navigator 负责"带路",
operator 负责"代填"。两者都只产出指令,真正的动作在前端执行。

## 就地操作当前页(消息带 `<当前页面快照>` 时**优先**走这条)

如果用户消息里带了 `<当前页面快照 page="...">…</当前页面快照>`,说明用户**正看着
某个页面、想就地操作它**(搜索/筛选/在本页查询等)。这时**不要查目录、不要跳转**,
直接对着快照里列出的「搜索字段」「可用按钮」生成一条 `qwenpaw:operate` 指令:

    ```qwenpaw:operate
    {"mode":"current","page":"<快照里的 page>",
     "fill":[{"label":"<字段label>","value":"<值>"}],
     "click":"<按钮文案,如 搜索>","risk":"query","title":"<一句话说明>"}
    ```

- `fill`:要填的字段,`label` **必须用快照里给的字段名**,`value` 从用户话里取。
- `click`:填完要点的按钮(查询类点「搜索」)。
- **表格行内操作**(快照里有「表格每行可操作」时,如下载/查看某一行):用 `row`
  定位某行再点它的按钮——
  `{"mode":"current","page":"…","row":{"match":"<那行的特征,如某日期/名称>","click":"下载"},"risk":"query","title":"下载某行数据"}`;
  也可 `"row":{"index":3,"click":"下载"}` 按行号。`match` 用用户说的那行的特征文案
  (前端按单元格文字找行)。下载/查看=只读直跑,删除=写操作待确认。
- **本页"新建"等写操作**:用 `open` 让前端点开弹窗、**现场自省弹窗字段**、在对话里逐个
  填——`{"mode":"current","page":"…","open":"新增","risk":"create","title":"新建XX"}`
  —— 前端会点「新增」开弹窗 → 把弹窗字段在聊天里弹卡片/chips 让用户填 → 高亮「确定」由
  用户提交。你**不用知道弹窗里有哪些字段**(前端现场自省),只给 `open`(开弹窗的按钮文案)即可。
- `risk`:**只读**(搜索/筛选/查询/下载/查看)用 `query` —— 前端自动点、直接出结果;
  **写操作**(新增/删除)用 `create`/`delete` —— 前端只填好/定位,由用户点确认。
- 把指令块**原样**放进回复(前面可加一句自然语言说明)。前端会就地执行。

只有当**快照不存在**、或用户诉求**这页干不了**(要去别的页面新建等)时,才回退到下面
的目录匹配 + 跳转流程。

## 核心动作只有两个脚本

### 1) 识别操作 + 看需要哪些参数

```bash
cd skills/page-operator
uv run scripts/find_op.py "<用户原话>"
```

- **命中单个操作**:脚本会列出该操作的字段。**从用户原话里抽取他已经明确给出
  的参数**(如"标题叫停机"→title=停机),然后**立即** `emit_action`。
  - **不要逐字追问、不要等参数齐。** 用户没给的字段,前端会在聊天里**逐个弹
    卡片/选项 chips 让用户补全**(文本→输入卡、下拉/单选→页面真实选项 chips、
    日期→日期卡)。所以你只把"用户已经说了的"`--set` 上即可,其余交给前端。
- **多个相近**:脚本列出候选,请用户用编号/名称确认后再继续。
- **没匹配到**:如实告诉用户"暂不支持该操作 / 还没登记",别硬凑,也别
  自己去点页面。

### 2) 参数齐了 → 产出动作指令

```bash
# 推荐:逐项 key=value,免 JSON 转义
uv run scripts/emit_action.py <op_id> --set 字段=值 --set 字段=值
# 或内联 JSON
uv run scripts/emit_action.py <op_id> --params '{"字段":"值"}'
```

> 本工作区脚本统一用 `uv run`(与 real-alarm 等技能一致);若环境无 uv,可退回
> `python3`(或运行时的 python 解释器)。

- 脚本**总会**输出一段话术 **以及** 一段 ` ```qwenpaw:action ``` ` 指令块
  (匹配到即出,不会因缺参拦你)。**把脚本输出原样回复给用户,指令块必须逐字
  保留、不要改写。** 前端会:跳转 → 打开新增弹窗 → 把你给的参数预填 → 对没给的
  字段逐个弹卡片/chips 让用户补全 → 最后用户确认提交。

## 行为准则(写操作的命门)

- **永远不要声称"我已经提交/已经新建好了"。** 你只是"把表单填好了,请您
  确认后点提交"。真正的提交由用户在页面上点击,走页面真实校验与接口。
- **只 `--set` 目录里声明的字段**,不要无中生有加字段,也不要替用户编造他没
  提到的值——没给的字段交给前端弹卡片让用户自己补,别擅自填默认值。
- **删除 / 批量 / 高风险操作**(risk=delete 等)措辞要更谨慎,明确告知后果。
- 不泄露接口 token / Authorization 原文。
- 含糊的查询、看数据、纯跳转的诉求不归本技能:那是普通对话 / page-navigator
  的事。本技能只处理"在某个页面上新增/录入一条记录"这类写操作。

## 操作目录

能识别哪些操作由 `catalog/operations.json` 决定。新增/维护操作用
`scripts/scan_catalog.py` 从前端工程半自动抽取后人工 review(见脚本
`--help`)。指令块格式与前端如何执行,见 `references/action-contract.md`。
